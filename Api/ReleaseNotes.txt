v5.1.0

**BREAKING CHANGES:**
* GD-477, GD-522: The minimum supported Godot version is now 4.7, older Godot versions are no longer supported.
          Projects using Godot 4.6 or older must upgrade to Godot 4.7 or newer.
* GD-545: Added the typed scene runner `ISceneRunner<TScene>`, `ISceneRunner.Load(new Player())` infers the scene type
          and `ISceneRunner.Load<Player>("res://player.tscn")` loads by path, failing with a message naming the expected and the actual type.
          `Scene()` never returns null anymore. After the scene runner is disposed, `Scene()` and every member that uses the scene,
          the input simulation or the time factor throw an `ObjectDisposedException`.
          Casts on `Scene()` become redundant (IDE0004) and fail the build in projects that treat warnings as errors, null checks become redundant.
          Migration: remove them, e.g. `(Player)runner.Scene()!` becomes `runner.Scene()`, and expect the exception after `Dispose()`.
          Loading by path with `ISceneRunner.Load("res://player.tscn")` still returns `Node`, switch to `ISceneRunner.Load<Player>("res://player.tscn")` first.

* GD-317: Fixing [IgnoreUntil] is not skipping the test.
* GD-318: Fixing object deep equal comparison.
* GD-319: Fixing SceneRunner.Scene() returns disposed object after the scene is auto freed, since GD-545 it throws an `ObjectDisposedException` instead.
* GD-320: Fixing method Chaining on Asserts breaks type inference after base interface methods,
          fixes also dynamic assert bindings (missing public access).
* GD-331: Fixing SceneRunner SimulateKey to provide missing Unicode
* GD-333: Fixing broken Signal assertion task handling
* GD-339: Fixing to allow single `NULL` value as TestCase argument e.g `[TestCase(null)]`
* GD-340: Fixing GdUnit4NetApiGodotBridge test discovery on linux paths
* GD-348: Fixing task handling using AwaitMethod with WithTimeout
* GD-366: Fixing `NO Godot C# SUPPORT NOT DETECTED` by increasing the used timeout to capture the supported arguments
* GD-436: Fixing named pipe collision when running multiple assemblies in parallel
* GD-437: Fixing respect CompileProcessTimeout in dotnet build step
* GD-446: Removed unused dependencies `Moq` and `CommandLineParser` from gdUnit4.api.
          If your project relies on either, add them explicitly to your .csproj.
* GD-466: Fixing a failing Godot runtime exit is reported without a cause.
          The runner now reports the exit code, the signal name of a crash (e.g. `SIGSEGV`, `SIGABRT`)
          and the last 30 lines of the Godot error output, and states whether all test results were reported before.
          The connection to Godot is now closed before the engine shuts down.
* GD-493: Fixing the Godot C# support check, which failed randomly on a slow Godot start
          and skipped all tests that require the Godot runtime.
          The check now reads the version of the Godot binary and also detects Godot builds without C# support.
* GD-492: Fixing the object deep equal comparison, which skipped a property when comparing its value threw an exception.
          The exception now reaches the test, properties that cannot be read (indexers, throwing getters, ref struct values) are still skipped.
* GD-526: Fixing the stdout capture of a test, which lost the Godot output written right before the capture stops,
          and on Windows kept reading after the capture stopped and took the output of a later capture.
* GD-528: Fixing the conversion of a `decimal` to a Godot `Variant`, which always failed, a `decimal` is now converted to a `float`.
* GD-532: Fixing the named pipe collision when the same test assembly runs in parallel, e.g. from two checkouts or CI jobs on one machine.
          Each run now uses its own pipe to the Godot runtime.
* GD-453: Fixing the SceneRunner delivering each simulated input event twice to `_UnhandledInput` and `_GuiInput` of the scene root.
          Simulated events now pass the Godot input pipeline only, `_GuiInput` of an unfocused Control no longer receives key events.

✨ Improvements
* GD-311: Verify the Godot binary has C# support before running godot runtime tests to avoid invalid test execution.
          If the binary not supports C#, all tests marked with [RequireGodotRuntime] will be skipped.
          The logger now uses the prefix `[GdUnit4]` and additionally marks the output with a tag
          - `:build:` for compilation tasks
          - `:stdout:` for standard output messages.
          - `:stderr:` for standard error messages
* GD-314: Allows the use of `OverrideFailureMessage` only at the beginning of the assertion chain to avoid errors.
    ```
    AssertString("foo").OverrideFailureMessage("Custom failure message").IsEqual("bar"); // ✅
    AssertString("foo").IsEqual("bar").OverrideFailureMessage("Custom failure message"); // ❌ Compile error
    ```
* GD-332: Do not allow returning null values on AutoFree to avoid spamming warnings
* GD-426: Add ambient LoggerFactory and LogCapture for testing
* GD-443: Make Godot runtime connect timeout configurable in ``.runsettings`
   ```
   <!-- GdUnit4-specific configuration -->
       <GdUnit4>
            <GodotConnectTimeout>10000</GodotConnectTimeout>
       </GdUnit4>
   ```
* GD-477: Add support of `PackedVector4Array` on Variant assertions, which failed before with a `NotImplementedException`
* GD-484: The package now targets `net8.0` and `net10.0` (C# 14) instead of `net8.0` and `net9.0`.
* GD-530: The test engine reports why tests were not executed, a crash of the Godot runtime with its exit code and signal or the test session timeout,
          to the new `ITestEventListener.ReportNotExecutedCause`, which has a default implementation that ignores the cause.
          The supported .NET versions are .NET 8 and .NET 10, projects targeting `net9.0` use the `net8.0` build.
* GD-485: Removed the `Microsoft.CodeAnalysis` and `Microsoft.CodeAnalysis.CSharp.Workspaces` dependencies, the async data point timeout now reads its source location from the debug symbols.
* GD-486: Replaced `Newtonsoft.Json` by `System.Text.Json` on the pipe to the Godot runtime, which now accepts only the known message types, the package no longer depends on `Newtonsoft.Json`.
* GD-511: Creating a test from the Godot editor supports methods and properties of structs, interfaces and records, of nested types
          and of every type in a file with several types, the test suite is named after the type that contains the selected line.
* GD-539: Tests can live in a separate project that references the Godot game project with a `ProjectReference`.
          At test runtime the referenced project is mounted: its scenes and resources load by `res://` and `uid://` paths,
          and its input map, autoloads, project settings and audio bus layout are applied. Its assets are imported only when they changed.
          Cache invalidation hashes project files and the Godot binary, so timestamp-preserving content changes are detected.
          Settings that require restart keep the test project's startup values.
          Set `<GdUnit4MountGodotProjectReferences>false</GdUnit4MountGodotProjectReferences>` to turn it off.

## 📋 Migration Guide:

**Before v5.0.0:**
```csharp
[Test]
public void MyTest()
{
    // All tests ran in Godot runtime
    var node = new Node();
    AddChild(node);
}
```

**v5.0.0:**
```csharp
[Test]
public void MyLogicTest()
{
    // Runs fast without Godot runtime
    var result = Calculator.Add(1, 2);
    AssertThat(result).IsEqual(3);
}

[Test]
[RequireGodotRuntime]  // Required for Godot-dependent tests
public void MyGodotTest()
{
    var node = new Node();
    AddChild(node);
}

[Test]
[DataPoint(nameof(TestData))]  // Data-driven tests
public void TestCalculations(int a, int b, int expected)
{
    AssertThat(Calculator.Add(a, b)).IsEqual(expected);
}

[Test]
[ThrowsException(typeof(ArgumentNullException), "Value cannot be null")]
public void TestValidation()
{
    Calculator.Add(null, 5); // Expects specific exception
}

public static IEnumerable<object[]> TestData => new[]
{
    new object[] { 1, 2, 3 },
    new object[] { 5, 7, 12 }
};
```

## ⚙️ Configuration:

New `.runsettings` options:
```xml
<RunSettings>
  <GdUnit4>
    <CaptureStdOut>true</CaptureStdOut>
    <Parameters>--verbose --headless</Parameters>
    <DisplayName>FullyQualifiedName</DisplayName>
    <CompileProcessTimeout>30000</CompileProcessTimeout>
  </GdUnit4>
</RunSett>
```

This release represents a major evolution in GdUnit4's architecture, providing developers with the flexibility to write fast, efficient tests while maintaining full Godot integration capabilities when required.
